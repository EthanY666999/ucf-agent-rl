# UCF-v2.2 / v2.2-ff 发布状态

本轮只更新4B发布计划与启动门禁。**尚未取得并同步2B正式验收通过的v2.2／v2.2-ff源码。** 名称更新不是算法已经实现，也不是允许启动训练。

## 等待同步的定义

- SFT-UCF：v2.2；第k题的c_k只由其他题候选求解，不可达时沿用可达上限规则。p̂₋ⱼ与基线仍排除当前轨迹；β、ρ_min、F、预算、奖励与优势定义不变。
- 反事实：覆盖原动作层完整补集。具体节点概率口径、采样失败的处理及无偏性必须以2B最终验收的冻结版本为准，本仓库不自行选择另一种实现。
- 无SFT：v2.2-ff；首个开围栏之后定义节点，不跳空白；首个完整动作块结束处按实际采样token边界截断，同步截取ids、old_logprobs与mask，训练／评估协议一致。该协议还须在无SFT对照组一致实施，不能把旧F02当作配对新基线。
- 前缀检查固定其他题和本题另外三条轨迹，改变被检查轨迹节点后的内容；检查该题c_k及该轨迹前缀未变节点的ρ。不要求另外三条轨迹的ρ在p̂发生合理变化时也不变。

## 同步与放行证据

至少需要：2B代码与配置SHA256、依赖版本、因果与支持集测试收据、包含残余质量和小补集概率的数学检查、实际GPU采样与训练冒烟、对应格式协议的轨迹回放。SFT版本与ff版本分别验收，不以其中一个代替另一个。

接收后核对文件哈希，记录相对S05 v2的全部实际差异，再更新独立发布的源码／入口和清单，重跑CPU验收。此前`code/release_admission.py`在直接训练入口与统一启动器中拒绝所有UCF执行；删除配置gate或换版本字符串也不回退旧v2。此门禁不涉及设备部署实现。

## 历史保留

2B S05使用v2，当前发布保留其源码与结果。v2是整批c及受限动作集合采样，不能当作新的v2.2运行。旧v2.1的失败记录不删除，也不声称其已变成v2.2。

难版FrozenLake的UCF还有独立起点门禁：4B-07等待2B H01后统一选择SFT协议。仓库中难版Golden Trace数据的存在，不代表它已获选为训练输入。
