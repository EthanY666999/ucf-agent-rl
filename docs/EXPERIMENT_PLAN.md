# 合作者 4B / 9B 实验任务书

本任务书只管新发布的合作者实验，不控制现有2B服务器。现有S05和80G队列顺序保持不变。发布先交负责人审阅，审阅前不向合作者发送、不自动启动训练。

## 先读资源限制

**本包尚未GPU验收4B或9B。当前全参数训练器不能被当成“单张80GB可直接跑”。** 精确CPU参数核算见 [MEMORY_AND_RUNTIME.md](MEMORY_AND_RUNTIME.md)：4B静态actor、梯度、优化器、reference与vLLM权重合计78.34GiB；9B为166.78GiB，均未包含激活、KV cache等。4B需要足够显存且完成实际冒烟；9B需要训练状态分片等适配，单独把vLLM移到另一张卡仍不足以解决训练侧133.42GiB静态状态。本包未验证的多卡/FSDP能力不得写成可用。

因此下面是**实验顺序与预算**，不是已获GPU可运行认证的自动队列。任何对应硬件/实现门禁未通过的项目保留“待验收”，不靠减小group、修改优势、改奖励或改步数绕过。

## 共用协议

- 模型分别为Qwen3.5-4B、Qwen3.5-9B。先下载tokenizer/config做CPU验收；正式GPU阶段由合作者另行准备完整权重，本仓库不含权重。
- 保持2B的算法参数：RL 400步、每批64题、GRPO group4、Random K=2、UCF β=0.25、ρ_min=0.03、目标分叉数2及原权重/优势/奖励。FrozenLake/Sokoban配置从实际2B配置派生，只调整模型/资源/便携路径。
- 默认seed42，完成主线后补seed43。同一环境的冻结专家数据供不同模型规模使用；每个规模独立训练SFT并导出模型，同环境全部RL分支从该**同一个SFT导出模型**独立开始。Sokoban/难版FrozenLake各1000条多回合样本，1 epoch、batch16为63步。ALFWorld是1000个完整episode，经history=2转为**15857条逐步独立样本**，1 epoch、batch16且保留尾批为**992个优化器更新**，不能写成63步。ALFWorld完整SFT训练入口尚未集成，这个992是冻结预算计算，不是已跑完的训练。
- seed43默认重复RL主臂，仍复用该规模、该环境已冻结的同一个SFT起点，从而只改变RL随机种子。额外改变SFT seed必须另列实验，不混入此对照。
- 每25步验证，保留0、25、…、400的固定验证记录；最终400步做冻结测试集评估。禁止按测试集挑checkpoint。
- 网格环境`max_response_tokens`限制一整条轨迹累计assistant采样token（原始模型4096，SFT后10240），不是每回合重新获得额度。ALFWorld独立评估入口当前采用每回合4096及history=2重建上下文，属于独立协议；其RL接入时须冻结轨迹/回合预算和采样参数，不能仅凭同名字段宣称预算相同。
- 一次只运行一个实验。一个实验可以在事先验收过的多卡资源组上运行，不能把每张卡各开一条无关训练。
- 无SFT UCF、ALFWorld UCF当前**被v2.1验收失败阻塞**：2026-11-09全量F02审计的首动作/最终解析不一致12.8053% > 2%，且残余动作支持的无偏性模拟失败（max z=149.4415）。必须解决方法定义与支持问题、重新完成2B验收并获得明确版本/收据后才能排训练。功能CPU测试通过不是该许可。4B的SFT-UCF主线按v2运行，保留其已知局限。
- ALFWorld采用50步上限、可执行动作列表、官方valid_seen=140/valid_unseen=134与[ALFWORLD.md](ALFWORLD.md)冻结的history=2窗口。该环境已提供真实CPU环境、1000条专家回放及独立基座评估入口；**完整SFT/RL训练适配尚未完成**，不能直接调用四方向trainer。独立基座评估不依赖训练侧分片，可在单独推理资源验收后进行，但不是本发布已完成的GPU成绩。必须披露模型、采样预算、训练预算和提示词差异；环境设置一致不等于能把分数直接当作已发表模型的同条件复现。

## 时间与磁盘预算的读法

2B当前A10080G实测参考：Sokoban SFT约12.15分钟；S03 GRPO4的400步约5.60小时；S04 Random K=2约11.33小时；S05前78步外推400步约16.65小时（未完成值）；SFT模型main100评估约22秒、原始模型约4.32分钟。均不包括下载、环境安装、故障等待。

同卡、同token量的**参数量线性规划参考**采用4B/2B=2.235，9B/2B=4.758；对应4B Sokoban SFT约27分钟、GRPO4约12.5小时、Random约25.3小时、UCF约37.2小时；9B约58分钟、26.6小时、53.9小时、79.2小时。**这些不是实测ETA**，当前模型还需要不同的显存部署，推理长度变化可使误差很大。正式排期应以目标硬件5–10步冒烟后测得的中位秒/步更新。

对尚无基准的难版FrozenLake和ALFWorld，不虚构小时数。定义 `T_RL = t_val_initial + 400 × t_step + 16 × t_val + t_final`（若`step_seconds`已包含验证，应扣除重复项），`T_SFT = ceil(N_sft_rows / 16) × t_sft_step + t_export + t_eval`；Sokoban/难版FrozenLake的N为1000，ALFWorld的N为15857。时间符号都由该环境的实际冒烟/评估测量后填写。表中“待测”意味着不能承诺完成日期。

磁盘：4B每个活动训练预留至少**130GiB + 轨迹/日志**；9B至少**275GiB + 轨迹/日志**，覆盖训练checkpoint、原子更新临时副本和最终模型。基础模型另预留约8.68GiB/17.98GiB，每保留一个FP32最终模型另占15.67GiB/33.36GiB。CPU源码/数据验收不占模型权重空间。运行所有臂时先累计要保留的最终模型，不能把“每活动run”当整个项目总空间。

2B Sokoban已完成400步的压缩rollouts为S03约29MiB、S04约47MiB，S05前80步普通rollouts约12MiB、ucf_logs约49MiB；它们只说明短动作场景的历史量级，ALFWorld/无SFT长推理可能大很多。

## 验收与交回

1. 安装和CPU测试按 [INSTALL.md](INSTALL.md)。验收模型revision、tokenizer/vocab、围栏和动作id、模板及数据哈希，保存输出。
2. GPU冒烟只检验目标模型加载、采样/训练/导出/重载、概率一致性、分叉/权重和有限梯度；不要把1步高reward当算法成功。
3. 正式训练前冻结配置和源码SHA256。模型加载失败、哈希不一致、KL异常、非有限loss/梯度、分叉数异常时，保留日志和checkpoint，停止该组并向负责人确认；不得私改β、ρ_min、目标预算、奖励或评估集。
4. 每25步记录固定验证（ALFWorld接入时须另外冻结训练内验证划分，官方seen/unseen终测不用于选模型）、初始全失败/混合/全成功组、含分叉叶子的同类统计、翻转率、救回率、actual/expected forks、KL、token成本、耗时。明确分母和窗口。
5. 交回新仓库的`results/<model>/<environment>/<run_id>/`：配置、源码/数据/模型revision与哈希、train_metrics、全部验证/终测汇总及逐题结果、ucf_logs（含选点和权重诊断）、运行耗时/显存/磁盘峰值、失败说明。只提交轻量文本，超大证据压缩分片并列SHA256；不交权重或checkpoint，不把raw rollouts批量推到仓库。
6. 权重留合作者自己的受控存储。一个实验只有400步完成且终测核对后，才可依据保留策略清理恢复checkpoint。原子存盘时必须留够新旧两份空间。
7. 不将结果提交旧仓库；不覆盖历史聚合快照。README和任务书中的“进行中/待验收”只有附上对应验收记录后才能改为完成。
