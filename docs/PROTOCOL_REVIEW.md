# 发布时的新协议审查

2026-11-09，只读代码核验与CPU反例。本页记录待审方案，不代表本发布已部署这些改动；运行中的S05保持原实现。

## 当前控制器不是留一题校准

生产 `ucf_collect.py` 的104–110行把全部题目的候选权重送进一次 `calibrate(target=2.)`，再给全部节点使用同一个 `c_step`。复制后远程文件再次核验SHA256为 `006c370c3a9c37a9b0a2d63b853e4f0c541e21988d4e59af48e27469298ee85d`。发布保留该实际实现，不用预期设计替代事实。

调用实际CPU函数：两题各有4个权重1的候选时，c=0.5、固定节点ρ=0.5；只给第一题的轨迹后面增加两个权重1的候选，第二题与原节点前缀/权重不变，c与该节点ρ降至0.4。该变化由本题的未来候选触发，不是其他题正常变化。

这证明当前实现不符合此前约定的留一题、前缀因果协议。**不能仅凭此反例判定全部HT估计有偏**：在ρ为正且被正确记录/使用时，条件于完整数据D仍有 E[I Z/ρ | D]=Z。格式排除ρ=0、动作支持缺失及成对估计目标需分别检查。

正确的局部验收应固定其他题，以及同题另外三条轨迹，改变目标轨迹节点后的内容，检查该节点的选点概率不变。改变同题其他轨迹的奖励会按设计改变leave-one-trajectory-out成功率/基线，不能把那种变化误报为bug。实现留一题c时须排除整题，而不只排除当前节点。

## 首个动作块停止协议

在第一个完整围栏块结束时停止可以在线因果实现，但改变了原先可能使用末块动作的生成/解析协议。新无SFT GRPO/Random/UCF及评估必须统一使用；未闭合、非法动作、EOS/预算截断需单独记录，不能只保留格式成功样本。F02旧协议不能作为新协议的唯一配对基线。SFT轨迹是否逐位不变必须由实际token ids/old_logprobs/mask/环境动作回放验证，不能由“通常只有一块”推断。

## 不建议跳空白后再定位

“第一非空token出现的时刻”虽是停止时刻，但其前一刻的前缀是否被选中，已经利用了下一token非空这一信息。原token来自条件分布π(x|h,x非空)，反事实若仍采含空白的π，二者不一致。

精确枚举反例：π(W)=1/2，π(A)=π(B)=1/4，STAY={W,B}、GOAL={A}。筛为非空后原样本A/B各1/2。即使反事实采完整补层，层质量加权估计对f(W)=1、f(A)=f(B)=0的期望为1/4，原π期望为1/2。最小稳妥方案保留固定首个开围栏之后的节点；需要条件策略时应另行定义并重推，不能把它叫不影响算法的小修。

## 补层采样的必要条件

目标是 q(x|h)=π(x|h)·1[x不属于C_o]/(1−π(C_o))。须完整覆盖词表分区；p[0]只是未建模首token质量，不自动等同环境无效/STAY。原层若含OTHER/STAY，要排除整层，而非只屏蔽几个方向词。首token的代理层与完整回复的真实后果之间仍需核对。

vLLM0.19.1的直接 `SamplingParams(logit_bias={id: -inf})` 保留负无穷；`from_optional()` 则把bias裁到[-100,100]。后者不是严格硬屏蔽。需验证实际入站路径、批处理交换与概率归一化，并保持训练温度1、top_p=1、top_k=-1、无额外改变分布的penalty。old_logprob使用原始π是必要条件，但单靠它不能修正错误的q。
