# 实验背景、已有结果与已知局限

> 只读核对日期：2026-11-09。2B 结果快照截至 S05 第 78 步；这是历史发布快照，不是实时看板。4B、9B 尚无本仓库 GPU 训练结果。机器可读数值、统计窗口、原始文件 SHA256 见 [summary.json](../data/evidence/summary.json)。只发布汇总，不发布内部日志或权重。

## 从 PaTR 复现到 UCF

项目先以 Qwen2.5-0.5B-Instruct 在 FrozenLake 上重建 GRPO、PaTR 和 Tree-Random，随后加入 Golden Trace SFT，并研究如何把有限反事实采样预算放在更有训练价值的决策点。UCF 在四条初始轨迹的组相对更新之外增加选点、后果分层和反事实辅助更新。它仍是研究中的方法：0.5B 有正向结果，也有较大训练种子方差和无 SFT 冷启动负面结果；2B 用更难环境验证收益、成本和稳定性，不能把采样诊断改善直接当成终测提升。

## 口径

- Success rate 是成功轨迹数 / 总轨迹数；pass@4 是四次采样中至少成功一次的题目比例。两者不能互换。
- main100 是固定 100 题 × 4 轨迹；supplemental500 / all500 为固定 500 题 × 4；filtered409 是历史重叠敏感性分析集合；map8 是另一个环境集合。它们不混成一个分数。
- 下表中的验证结果不能作为最终测试结果；中途最好验证不代替末步结果。
- 0.5B 属于历史协议，2B 的模型、环境与实现不同。跨版本数字描述研究过程，不构成受控的模型规模消融。

## 2B：为什么转到 Sokoban 与难版 FrozenLake

原版 FrozenLake 的 F02（无 SFT→GRPO4、400 步）最终 main100 是 **93.0 / 97.0**，supplemental500 **94.4 / 97.8**，map8 **98.0 / 100.0**。因此“93–98%”是不同测试集合的 success 范围，不是一条统一指标。对主要短路径任务已接近上限，继续只在该集合比较容易掩盖方法差异，于是加入 Sokoban 和 BFS 筛选的难版 FrozenLake。

Sokoban，seed42：

| 运行 | 状态 | main100 最终 success / pass@4 | supplemental500 最终 success / pass@4 |
| --- | --- | ---: | ---: |
| S01 原始模型 | 评估完成 | 8.25 / 20.00 | 9.35 / 20.60 |
| S02 Golden Trace SFT | 1000 条、1 epoch、63 步完成 | 43.00 / 61.00 | 39.10 / 57.00 |
| S03 SFT→GRPO4 | 400 步，完成核验 | 75.25 / 76.00 | 77.00 / 77.60 |
| S04 SFT→Random K=2 | 400 步，完成核验 | 76.50 / 77.00 | 79.30 / 79.80 |
| S05 SFT→UCF v2 | **进行中，78/400** | 尚无最终测试 | 尚无最终测试 |

S05 第 50 步验证为 72.50 / 77.00，第 75 步为 **74.75 / 77.00**。相同第75步，S03 是 77.50 / 80.00，S04 是 73.50 / 75.00：S05 暂低于 GRPO4，但高于当步 Random；不代表终局排名。

S04 训练生成 token 为 4,834,692，S03 为 2,705,733，即 **1.787 倍**；main100 提升 **1.25** 个百分点，supplemental500 提升 **2.30** 个百分点。输入 token 为 2.094 倍，耗时也不等同于生成 token 比例。这里“约1.8倍换约2点”只作为粗略描述，正式表格必须用上述精确口径。

## 信号诊断：不要把翻转率写成救回率

S05 前75步与 S03/S04 前75步比较：

| 指标 | S03 | S04 | S05 |
| --- | ---: | ---: | ---: |
| 初始四条中的混合组数，均值/64 | 14.08 | 此旧日志未直接记录 | 18.13 |
| 初始＋实际反事实叶子的混合组数，均值/64 | 无反事实 | 13.77 | 27.16 |
| 日志 KL 均值 | 0.1200 | 0.1343 | **0.8322** |

S05 第59–78步：初始四条混合组平均 **13.85** 道；加入实际反事实叶子后平均 **23.75** 道（20–34）。因此“混合组20–28道”不是全程严格范围，也必须明确是否包含分叉叶子。多采样本就增加混合组概率，不能只凭该数值证明算法更优。

**救回率**的分母是初始四条全失败的题，分子是其中至少有一条反事实成功的题。S05 前78步逐步平均救回率为 **8.93%**，最近20步为 **11.86%**。约20%的数字对应的是原/反事实奖励**翻转率**：前78步 **22.82%**，最近20步 **21.34%**。翻转包含成功→失败，不能当成“救回”。

S03 最后20步初始混合组平均仅3.60/64，S04全部叶子混合组平均3.35/64，说明零方差组占比很高。但全成功组与全失败组必须分开报告：前者可能是已学会，后者是仍没有成功轨迹。UCF 的候选/混合覆盖改善与验证落后、KL偏高可以同时成立；当前尚未证明净收益。

## v2 无 SFT 格式问题与 v2.1 的发布边界

现行 v2 要求回复的第一个 token 是动作围栏，首动作还需与最终环境解析动作一致，否则 rho=0。F02 已有 GRPO 轨迹的 CPU 离线回放抽取第1、2、3、4、5、25、100、200、300、400步，共2560条轨迹、7630次回复；6841个实际执行节点中6659个（**97.34%**）被排除，其中6115个能解析动作，只是动作前有解释文本。640题次里601题次完全没有合格节点。

这是假设应用 v2 过滤的资格统计，不是 F10 已经运行的训练结果，也不能直接当作 Sokoban S15 的排除率。S05 前58步的104482个候选只排除29个（0.0278%），平均实际分叉2.0016/题。已选节点的 `parse_mismatch_fraction` 天生接近0，应看全部候选的 `original_parse_mismatch_fraction`。

v2.1 在本回合第一个围栏之后保留已采推理前缀、在动作处采反事实。**2026-11-09 的独立隔离验收未通过，GPU admission 已关闭；不仅是“还没测”。** 本包保留实验性实现及测试以便审查，无SFT UCF与ALFWorld UCF不得启动，v2 仍用于现有 SFT 主线。

新增的全量 F02 离线审计覆盖400个训练文件、102400条轨迹、334426次回复：322741次有围栏（96.506%）；322721次在围栏后还有采样预算（占回复96.500%、覆盖轨迹98.224%）。这修复了“完全没有候选”的覆盖问题，但不等于训练器已正确：

- **动作语义门禁失败**：首围栏后立即动作 token 与原环境最终解析动作不一致为 **41328/322741 = 12.8053%**，超过预设2%阈值。分母包括围栏后已无 token、归入残余动作0的回复。没有修改原parser来掩盖差异。
- **无偏性模拟失败**：四动作完整支持的情况 max z=1.4841，通过；另加残余质量 p[0]=0.08 的合成情况 max z=149.4415，失败，且 Monte Carlo 与解析有偏估计一致（max z=1.9310）。原因是反事实支持集只含合法动作 token，残余 STAY token 缺少互补贡献。它是数学反例，不是已测得 F02/S15 梯度偏差为某个数值。HT 的1/rho只校正选点，不能补上动作采样支持缺失。

全量审计给出的期望分叉数2/题是满足支持条件时的校准数学量，**不是 GPU 实测分叉数**，也没有从 top-1 日志伪造全词表熵。原先11月7日两次有原始轨迹的冒烟分别为47回合（长度截断8、扣除截断后的格式排除39、可选0）和26回合（截断14、格式排除12、可选0）；更早两次没有保存原始轨迹，不能补造分类数。

前缀复制、suffix invariance、token打分、old_logprob与mask等功能测试通过，不等于总体CPU验收，更不等于GPU验收。首围栏定位不得读取之后的内容来重新选锚点；移除围栏梯度、改成条件动作概率会改变 v2 目标，不自动与 SFT v2 逐位等价。无SFT v2.1与SFT v2同时改变初始化和实现，不能称作严格只移除SFT的消融。历史v2结果不被此发布重写；上述数学反例涉及沿用的残余支持规则，也不能据此宣布v2在任意输出支持上已证无偏。

## 新发布的 ALFWorld 数据，不是新训练成绩

本包ALFWorld Golden Trace已经完成1000个不同训练任务的手写专家演示，并按`data/alfworld/golden/verification.json`在fresh environment逐步核对观察、动作、奖励和成功状态。独立检查实际文件：完整轨迹1000行；history=2的逐步SFT消息15857行、1000个episode_id，均标记train。1 epoch、batch16、保留最后不足16条的小批次对应**992步**，不是63步。

这些是CPU环境/专家数据与编码验收；没有4B或9B的ALFWorld GPU训练成绩。独立基座推理入口已提供，完整SFT/RL训练器、GiGPO状态锚点与UCF集成仍有独立门禁。专家可解任务筛选也带有选择偏差，不能把接纳率解释为全部训练任务的模型成功率。

## 实际踩过的坑

| 问题 | 已核对的证据 / 发布要求 |
| --- | --- |
| 重新分词破坏原采样轨迹 | `patr_core.apply_response` 直接使用 `out.token_ids` 和对应采样 logprob；后续拼接只追加新观察/模板后缀。禁止把历史回复 decode→encode 作为训练样本身份。 |
| Qwen3.5 空 think 块 | `chat_ids`/`turn_suffix` 从实际模板派生后缀；`test_q35_suffix_and_mask` 检查历史轮空 think 块、前缀不变和 assistant loss mask。仅“当前轮关thinking”不足以保证历史模板一致。 |
| 模型自己补 `</think>` | `enable_thinking=False` 是模板参数，不是硬性 token 禁令。`apply_response` 未拦截或删 token；保留原 token 并记录，不能静默改变采样分布。 |
| vLLM allowed_token_ids 别名 bug | 运行恢复收据：交换两个 mask 行时 RHS 都必须 clone，防止 torch view 覆盖；CPU复现原bug并完成57项实际方法交换检查。补丁只改运行库，不改算法。 |
| FrozenLake 全局 MAX_STEPS | vendored 环境构造器会改全局 MAX_STEPS；旧 DFS is_valid 也读它。难版生成器必须用独立 BFS 和冻结地图；不能运行时改全局筛选条件造成不同实验地图漂移。 |
| 无 SFT 4096 截断 | F02配置整条轨迹累计assistant回复token上限4096（`remaining=max_response_tokens-b.ntokens`，不是每回合4096）；F02主100最终有16/400轨迹 token_limit。F01、S01原始模型评估受到长回复限制，低分不能全归为任务推理能力。 |
| SFT 导出加载 | 保存后模型可能为 `qwen3_5_text`，vLLM入口仍需原始 `qwen3_5` 配置；兼容加载器对比 text_config，再同步精确 actor 权重，首次评估前必须完成。禁止误拿bootstrap底座权重评估SFT。 |
| 哈希清单过期 | S05恢复启动脚本显式检查冻结源文件和配置哈希；发布适配后必须生成新的发布清单，同时保留原生产来源哈希。不能靠删断言或伪造旧清单解决。 |
| 磁盘 | 2B含优化器训练checkpoint约22GB，最终模型另存；每次原子存档还需要临时文件空间。4B/9B按实际参数量重新预算，不能沿用22GB。只交轻量证据，运行中的checkpoint不得清理。 |

上述工程问题修复不等于科研效果验证通过。加载、采样、哈希、分叉预算异常必须保留证据并停止该实验请负责人判断，不能在合作者端自行改算法参数。
