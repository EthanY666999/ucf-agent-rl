# Storage and restart records for the two 50→100 continuations

The UCF and GRPO checkpoints at step 50 contain their respective model, AdamW and four RNG states. Their SHA256 values and original paths are in [anchors50.json](anchors50.json). The two serial runs, their configuration hashes and their stop at 100 are recorded in [bounded_plan.json](bounded_plan.json).

Five inactive FP32 model files from S03–S07 total 35.05 GiB. Their lossless archives total 18.30 GiB. Before releasing a plain copy, the CPU encoder reconstructed the complete safetensors file and compared its SHA256 with the original. The S02 weights used as the reference remain on the server. Each archived model directory records the exact restore command in `ARCHIVED_WEIGHTS.json`. The source, reference and archive digests and sizes are in [models_plan.json](models_plan.json). [FP32 archive and restore tool](../../../control/lossless_weight_archive.py)

The training code saves a new rolling checkpoint before replacing the previous one. Each step-50 checkpoint has a separate hard link until a later rolling checkpoint exists and the archived step-50 bytes have passed full reconstruction. The archive uses the retained UCF step-30 file as an immutable reference. The storage manifest lists each zstd part, the reference digest and the recovered checkpoint digest. A pointer beside the original step-50 path gives the restore command. Training and validation use the original precision and ordinary PyTorch checkpoint format.
