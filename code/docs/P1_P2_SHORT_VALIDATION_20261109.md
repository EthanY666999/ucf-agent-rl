# Sokoban P1/P2 短验证：预注册执行规则

状态：准备接入，必须等待 S06 完成训练、最终评估和核验。本文不是实验结果。

## 两臂与固定设置

均从 S02 的同一 SFT 模型独立开始，seed42；沿用 S05 的数据、模型精度、优化器、学习率、奖励、优势、β、F、回合限制和评估设置。

- P1：UCF-v2.2 + 可解性门控。候选的精确 BFS 最短剩余步数超过剩余回合数，或结构上不可解时，ρ=0，不生成 Part B。
- P2：P1 + 前三个回合的探索保底。对仍可解节点，ρ 下限为 `0.03 + 0.05 × (1 − p_hat_minus_j)`；`p_hat_minus_j` 只使用同题另外三条轨迹，依次对应 8%、6⅓%、4⅔%、3%。原评分概率更高时取更高者。
- 留一题校准包含新的逐节点下限，仍以平均每题 2 次分叉为目标；HT 使用实际 ρ。不可达时保留可达上限及诊断。
- 不启用 exact-FAIL、BFS-progress、max(S,H) 或其他评分变体。门控只使用动作之前的环境状态。

两臂的配置保留 `steps=400`，用命令参数 `--stop-after-step 150` 暂停。每 25 步固定验证，150 步保存模型、优化器和随机数状态；此阶段不做最终测试或 supplemental500 评估。每 10 步存档频率沿用 S05。

## 每 25 步与升级规则

报告相同 25 步窗口和累计数据：全错题不可解预算、救回率、前三步预算和平均 ρ、全错/混合/全对题数、固定验证 success/pass@4、KL、Part B 梯度范数及秒/步。

150 步时必须同时满足：

1. 全错题不可解状态的实际分叉占比 <10%。
2. 救回率严格高于 S05 的同一首 150 步参考。
3. 第 100、125、150 步验证成功率均值 ≥77.083333%。
4. KL 和 Part B 梯度范数完整、有限，且没有超过上述阈值。

两臂完成判定后，若都通过则优先 P2；只通过一臂则选择该臂。未通过或证据不完整的臂不继续训练。选中臂保存为 S05b 的逻辑标签，在相同目录和配置中从 150 续到总计 400，不重跑前 150 步。

## 队列与证据

执行顺序：S06 收尾 → P1 → P2 → S07 → S10（seed43、历史 v2）→ 若有合格臂，S05b 续跑 → 原队列剩余项目保持相对顺序。H05 仍使用原计划 v2.2。

控制器使用独立源码目录、独立验收和单 GPU 锁；不修改正在运行的 S06 源码，也不发停止信号。历史 GPU 验收仅作为环境和既有底座证据，不冒称新门控已有 GPU 验收。新选择逻辑先做 CPU 验收，P1/P2 本身提供运行证据。

模型和 checkpoint 只存远端。暂停的 checkpoint 保留；如需跨盘移动，先复制和核验完整哈希，保留原逻辑路径再续跑。完成 400 步后才运行最终测试、与 S05 的按题配对报告；测试结果不参与 150 步筛选。

## 解释范围

- S05 使用 v2，P1/P2 使用 v2.2。P1 与 S05 的历史比较同时含 v2.2 修正，不能把全部差异归因于门控；P2 与 P1 才隔离早期探索保底。
- ρ=0 的死局门控也移除了对应 Part B 的 KL 项，不能据此声称完整 PPO+KL 更新严格无偏。
- 不可解状态预算接近零首先证明门控实现生效，不等于成功率一定提升。
- 150 步、单种子筛选不是最终多种子性能结论，也不保证升级后成功率不下降。
